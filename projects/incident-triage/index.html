Separate the provider from the contract

The Worker supplies the actual model and Durable Object adapters to a shared request handler. The local fixture uses that handler with predetermined output and in-memory state. Its responses are labeled, and a synthetic provider error can be reproduced without an inference call.

The delayed-response race

Generation starts from a snapshot, while another request may change status or append a turn. Saving rereads current state inside a transaction and appends the successful conversation pair. Status and other committed turns survive; summary and hypotheses follow successful commit order. Concurrent requests may still generate from the same older context.

Keep the interface in the right session

Switching incident IDs invalidates pending view updates. Late replies, status responses and errors from an earlier visit cannot render into the new incident. Already submitted server work can still complete in its original session. Keyboard controls and labeled input support the local walkthrough.

What the fixture does not prove

A fixed response demonstrates application behavior, not model quality or root-cause accuracy. Local Durable Object checks exercise storage transactions without establishing deployed-service durability. The project has no authentication, sensitive-data redaction or history-retention policy. Demonstrations use synthetic incidents.
