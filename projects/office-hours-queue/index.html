Two ways to inspect it

The browser preview reuses the interface with fixed synthetic entries held in one tab. It makes no backend requests, collects no credentials or real phone numbers, and resets on reload. The local full-stack demo instead starts a loopback API with seeded demo credentials and a fake notification sender.

Authorization belongs in the API

Management mutations require a validated administrator token. Required startup configuration replaces fallback credentials, and public response projections omit internal phone numbers and hashes. Hiding a control in the guest view is not the authorization boundary.

The state boundary

The backend currently shares one queue and TA list across room codes, and all state disappears on restart. Duplicate admission uses a reservation before asynchronous hashing, which protects one process rather than a multi-instance deployment. Notification delivery is simulated in the demo and is not a durable outbox.
